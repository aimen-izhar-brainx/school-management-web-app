# T-020: Fixed Period schedule (backend)
- Milestone: M3
- Depends on: none
- Use cases: UC-16 (partial)

## Goal
Add the `Period` Prisma model and seed it once with the fixed 8:00 AM–1:00 PM, Monday–Friday school-day schedule (periods + breaks), per the `/plan` decision that periods are fixed and not admin-editable in v1.

## Definition of Done
- [ ] AC-16.3 Given the grid, when rendered, then its rows match the fixed schedule table above exactly: 6 teaching periods of 45 minutes and one "Recess" row from 10:15 to 10:45, starting at 8:00 and ending at 1:00. ("The fixed schedule table above" is the "Fixed school-wide schedule" table at the top of M3 in `docs/use-cases.md`; it is repeated in the technical notes below. Backend side: `GET /periods` returns exactly these 7 rows in order. The grid rendering is checked in T-023.)
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Prisma: add `model Period { id, order @unique, startTime, endTime, isBreak @default(false), label? }` and `enum DayOfWeek { mon tue wed thu fri }` to `backend/prisma/schema.prisma`, per `docs/plan.md`. Migration required.
- Seed script (e.g. `backend/prisma/seed.ts`, or extend the existing seed mechanism if there is one) inserts exactly these rows, as decided during /use-cases (see `docs/use-cases.md` M3 and the decisions log in `docs/plan.md`):

  | order | label | startTime | endTime | isBreak |
  |---|---|---|---|---|
  | 1 | Period 1 | 08:00 | 08:45 | false |
  | 2 | Period 2 | 08:45 | 09:30 | false |
  | 3 | Period 3 | 09:30 | 10:15 | false |
  | 4 | Recess | 10:15 | 10:45 | true |
  | 5 | Period 4 | 10:45 | 11:30 | false |
  | 6 | Period 5 | 11:30 | 12:15 | false |
  | 7 | Period 6 | 12:15 | 13:00 | false |
- Make the seed idempotent (upsert by `order`) so it can be re-run safely.
- `GET /periods` endpoint (any authenticated role, read-only) so the frontend grid (T-023) can render headers/break rows without hardcoding them.
- No write endpoints — periods are not editable via API in v1.
