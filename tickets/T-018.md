# T-018: Wire Sections UI (frontend)
- Milestone: M2
- Depends on: T-015
- Use cases: UC-06, UC-07, UC-08, UC-12

## Goal
Wire `ClassesPage`'s Sections area (create/delete section, assign class teacher) to the real `/classes/:classId/sections` API from T-015, replacing the mocked `TEACHER_OPTIONS`/local section state.

## Definition of Done
- [ ] AC-06.1 Given a valid, unique section name, when Admin submits, then it appears under the class immediately.
- [ ] AC-07.1 Given Admin confirms delete, when the request completes, then the section disappears from the list without reload.
- [ ] UC-07-E1 Given the section was already deleted by another session, when this admin confirms delete again, then shows "This section no longer exists." and refreshes.
- [ ] UC-07-E2 Given the only remaining section in a class is deleted, then the "No sections yet." empty state renders cleanly.
- [ ] AC-08.1 Given a teacher is picked for a section, when saved, then the section shows that teacher as class teacher immediately.
- [ ] UC-08-E1 Given no teacher accounts exist yet, when the class-teacher dropdown is opened, then it shows only "Unassigned" with no crash.
- [ ] AC-12.2 Given Teacher/Student view the Classes page, then the section write controls (add section, remove section, assign class teacher) are hidden or disabled.
- [ ] All tests pass. Reviewer approved. Verifier passed.
