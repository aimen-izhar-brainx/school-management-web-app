# T-037: Wire AttendancePage report tables to real API (frontend)
- Milestone: M3
- Depends on: T-035, T-036
- Use cases: UC-08, UC-09

## Goal
Replace the "Daily summary" and "Monthly attendance percentage" tables on the admin `AttendancePage` with real data from T-036's report endpoints.

## Definition of Done (copied from use cases)
- [ ] AC-08.2 Given a section has no session for the date, then its row shows "Not marked yet" instead of zeros (distinguishing "no absences" from "nothing submitted").
- [ ] UC-08-E1: Date is in the future → every section shows "Not marked yet".
- [ ] AC-09.2 Given a student has zero marked days in the selected month, then percentage shows as "—" (not 0% or a divide-by-zero error).
- [ ] UC-09-E1: Month filter set to a future month → all students show 0 marked days, "—" percentage.
- [ ] UC-09-E2: Section has zero enrolled students → empty table with "No students enrolled."
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Files: `frontend/src/components/AttendancePage.tsx` (its two report `<section>`s), co-located tests.
- Daily summary table: `GET /attendance/reports/daily?date=` on date change; render "Not marked yet" for any row whose `summary` is `null` (AC-08.2, UC-08-E1), reusing the same section list T-035 already fetches.
- Monthly table: `GET /attendance/reports/monthly?sectionId=&month=` on section/month change; render `percentage === null` as "—" (AC-09.2, UC-09-E1); render "No students enrolled." when the response is an empty array (UC-09-E2).
- No new data-fetching pattern needed beyond what T-035 already set up for the section picker — this ticket only touches the two report tables.
