# T-017: Link students to sections (backend)
- Milestone: M2
- Depends on: T-015
- Use cases: UC-07 (partial), UC-11, UC-12 (partial)

## Goal
Add the nullable `User.sectionId` field (the minimal link needed for M4's student timetable view, per `docs/plan.md`'s data-model decision) and an admin endpoint to assign/unassign a student to a section. Also complete the student-unassignment cascade for section deletion (UC-07's remaining piece from T-015).

## Definition of Done
- [x] AC-07.2 Given a section has students assigned, when the section is deleted, then those students' `sectionId` is cleared (students are not deleted, just unassigned).
- [x] AC-11.1 Given a student is assigned to a section, when fetched again, then the assignment persists.
- [x] AC-11.2 Given a student already assigned to a different section, when reassigned, then they are moved (removed from the old section, added to the new one) — a student belongs to at most one section.
- [x] AC-11.3 Given the student-assignment endpoint is called with a non-student user id, then it is rejected (reuses the `role=student` filtering from T-015's users-by-role endpoint for validation).
- [x] UC-11-E2 Given a student is unassigned (section cleared), then the student user is not deleted.
- [x] AC-12.1 Given a logged-in Teacher or Student, when calling the student-assignment endpoint, then responds 403 Forbidden and no data changes.
- [x] UC-12-E1 Given no token or an expired token, when calling this endpoint, then responds 401 Unauthorized.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Prisma: add `sectionId String?` + relation `"StudentSection"` to `User`, referencing `Section`. Migration required. (Deleting a `Section` with students assigned needs the app-level cascade from AC-07.2 — Prisma relations without `onDelete: Cascade` on a self-nullable FK require either an explicit `onDelete: SetNull` or doing the unassignment in a transaction before/during the section delete in `backend/src/classes/`.)
- Update the `Section` delete handler (in `backend/src/classes/`, from T-015) to clear `sectionId` for affected students as part of the same operation (transaction).
- Endpoint: `PATCH /users/:id/section` (body: `{ sectionId: string | null }`) in `backend/src/users/`, admin-only (`@Roles('admin')`).
- Reuse `GET /users?role=student` from T-015 to validate the target user is actually a student before assigning.
