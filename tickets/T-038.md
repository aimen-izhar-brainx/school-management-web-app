# T-038: GET /attendance/me endpoint (backend)
- Milestone: M4
- Depends on: T-032
- Use cases: UC-10, UC-11

## Goal
Let a logged-in student fetch their own attendance for a month, with no way to target another student's data.

## Definition of Done (copied from use cases)
- [ ] AC-10.1 Given the student has marked days in the selected month, then counts and percentage reflect only their own entries.
- [ ] AC-10.3 Given a day has no entry yet for the student, then it is simply omitted from the list (not shown as a blank/incorrect status).
- [ ] AC-11.1 Given Student A is logged in, when they call the endpoint, then only Student A's own entries are returned, with no parameter able to target another student.
- [ ] AC-11.2 Given Student A attempts to call the admin or teacher section/day endpoints directly, then they receive 403.
- [ ] UC-11-E1: A newly created student account with no attendance entries yet → empty list returned, not an error.
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- New endpoint in `attendance.controller.ts`, `@Roles('student')`: `GET /attendance/me?month=YYYY-MM`. The student id and section come only from `req.user.id` (JWT) — the route takes no student/section id parameter at all, so there is nothing for a client to override (AC-11.1).
- If the caller's `User.sectionId` is null, return `{ section: null, entries: [], present: 0, absent: 0, leave: 0, percentage: null }` (200, not an error) — mirrors the existing `GET /timetable/me` pattern for a student with no section (`timetable-me.spec.ts`'s `AC-20.1`). T-039 turns this into the "not assigned to a class yet" message.
- Otherwise: find the student's `AttendanceEntry` rows (via their `AttendanceSession`s for that section) within the given month, return `{ section, entries: [{ date, status }], present, absent, leave, percentage }` with the same percentage formula as T-036. No entries for a day → that day is simply absent from the list (AC-10.3).
- AC-11.2 is enforced by the existing `@Roles(...)` on the M1/M2 endpoints already excluding `'student'` — add a test confirming a student JWT gets 403 from `PUT /attendance/sections/:sectionId/days/:date` and the admin routes, as a regression check.
