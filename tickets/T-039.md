# T-039: Wire MyAttendancePage for students to real API (frontend)
- Milestone: M4
- Depends on: T-038
- Use cases: UC-10, UC-12

## Goal
Replace `MyAttendancePage`'s mock data with real calls to `GET /attendance/me` for the logged-in student.

## Definition of Done (copied from use cases)
- [ ] AC-10.2 Given the student changes the month selector, then the list and stats update to the newly selected month.
- [ ] UC-10-E1: Student has zero marked days in the month → "No attendance marked for this month yet," percentage shown as "—".
- [ ] UC-10-E2: Student requests a future month → same empty state as E1.
- [ ] AC-12.1 Given the student has no section assigned, when they open My Attendance, then a clear message is shown (e.g. "You are not assigned to a class yet.") instead of an error or crash.
- [ ] UC-12-E1: Student is later assigned a section by Admin → on next visit, My Attendance resolves normally with no stale error state.
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Files: `frontend/src/components/MyAttendancePage.tsx`, its co-located test file.
- This ticket wires the **student** role only. The mock's `user.role === 'parent'` branch (`findStudentByName`/`defaultStudent` fallback) stays exactly as-is and unwired, per `docs/plan.md`'s decision to defer parent access — don't remove it, just don't connect it to the real API.
- Replace `useLinkedStudent`/`INITIAL_ATTENDANCE_RECORDS` for the student branch with `GET /attendance/me?month=` on mount and month change (T-038); a `section: null` response renders "You are not assigned to a class yet." (AC-12.1) instead of the stats grid.
- Empty `entries` (zero marked days, whether from an all-unmarked month or a future month) renders the existing "No attendance marked for this month yet." empty state with percentage "—" — this already matches `calculateAttendancePercentage`'s existing null-handling, just confirm it's fed `null`/`0` correctly from the real response instead of mock data.
- UC-12-E1 is a no-new-code regression check: since the page re-fetches on every mount/visit (no stale cached state across sign-outs), a student assigned a section after initially seeing AC-12.1's message will see the normal view next time they open the page — verify with a test that re-renders with an updated `GET /attendance/me` response.
