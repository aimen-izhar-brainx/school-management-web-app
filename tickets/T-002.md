# T-002: Build shared DashboardShell/PageHeader component
- Milestone: M1
- Depends on: T-001
- Use cases: UC-01

## Goal
Extract the header/layout markup duplicated across all 11 post-login screens (the 10 new pages plus `RoleHome`/`AdminDashboardPage`) into one shared `DashboardShell` component, mirroring the existing `AuthShell.tsx` pattern used by the auth flow. The component must support both header variants seen today: sign-out-only with a back-to-dashboard link, and profile+sign-out with no back link.

## Definition of Done (copied from use cases)
- [x] AC-01.1 Given any migrated page, when it loads, then the header shows the GraduationCap icon + "Brainx School" text in the same position/style as before the refactor.
- [x] AC-01.2 Given a page that previously showed only a Sign out button, when rendered via the new component, then it still shows only Sign out (no Profile button added).
- [x] AC-01.3 Given the admin-dashboard/role-home variant, when rendered via the new component, then it shows both Profile and Sign out buttons.
- [x] AC-01.5 Given the non-dashboard variant, when rendered, then a "Back to dashboard" link (left-arrow icon) appears above the page title/content, and its `onClick` fires the passed-in callback.
- [x] UC-01-E1 Given a viewport narrower than 360px, when the header renders, then logo/title and buttons don't overlap or clip.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Reference pattern: `frontend/src/components/AuthShell.tsx` (split-screen shell reused by `LoginPage`/`ForgotPasswordPage`/`ResetPasswordPage`).
- Current duplicated header markup (identical across files): `frontend/src/components/{AdminCreatePage,ClassesPage,TimetablePage,AttendancePage,MarkAttendancePage,MyAttendancePage,MyTimetablePage,NoticeBoardPage,ProfilePage}.tsx` — each has:
  ```
  <header className="flex items-center justify-between border-b border-slate-200 bg-white px-6 py-4">
    <div className="flex items-center gap-2 text-lg font-semibold text-slate-900">
      <GraduationCap className="size-7" />
      Brainx School
    </div>
    <button onClick={onSignOut}>...Sign out...</button>
  </header>
  ```
  plus a separate `<button onClick={onBack}><ArrowLeft/>Back to dashboard</button>` below it.
- `AdminDashboardPage.tsx` and `RoleHome.tsx` have the same header but with an extra Profile button before Sign out, and no back-link.
- Suggested API: `<DashboardShell onSignOut={...} onBack={...}>` (back link rendered only when `onBack` is passed) plus an optional `extraActions`/`onOpenProfile` slot for the Profile button variant.
- This ticket only builds and unit-tests the component in isolation — it does not yet migrate any page (see T-003, T-004).
- AC-01.4 and edge cases UC-01-E2/E3 depend on real page wiring (`onSignOut`/`onBack` callbacks calling into `App.tsx`'s session logic) and are verified in T-003/T-004 instead.
