# T-036: Daily summary + monthly percentage report endpoints (backend)
- Milestone: M3
- Depends on: T-032
- Use cases: UC-08, UC-09

## Goal
Add the two admin report endpoints: per-section present/absent/leave counts for a date, and per-student present/absent/leave/percentage for a month within a section.

## Definition of Done (copied from use cases)
- [x] AC-08.1 Given a section has a recorded session for the selected date, when Admin views the daily summary, then that row shows correct present/absent/leave counts.
- [x] UC-08-E2: School has zero sections → empty report, no crash.
- [x] AC-09.1 Given a student has N marked days in the month with P present, then percentage = round(P / N × 100).
- [x] AC-09.3 Given a student was added to the section partway through the month, then only days with an actual recorded entry for them are counted.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- New endpoints in `attendance.controller.ts`, `@Roles('admin')`:
  - `GET /attendance/reports/daily?date=YYYY-MM-DD` — for every `Section`, look up its `AttendanceSession` for that date (if any) and summarize its entries' statuses; a section with no session for that date is reported distinctly (e.g. `summary: null`) so the frontend can render "Not marked yet" (T-037) instead of zeros. Zero sections → `[]`.
  - `GET /attendance/reports/monthly?sectionId=&month=YYYY-MM` — for every student currently in that section, scan that section's `AttendanceSession`s within the month and their entries for that student; return `{ student, present, absent, leave, markedDays, percentage }` with `percentage: markedDays > 0 ? Math.round((present / markedDays) * 100) : null` (AC-09.1). Only count days where an `AttendanceEntry` actually exists for that student (AC-09.3 — naturally true since a student only has entries for sessions submitted while enrolled).
- Both are read endpoints with no side effects — straightforward Prisma aggregation queries, no new models needed.
