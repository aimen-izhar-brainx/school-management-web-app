# T-005: Build shared Input/Select primitives and email validator
- Milestone: M2
- Depends on: T-001
- Use cases: UC-02

## Goal
Extract the repeated Tailwind-styled text input/select markup into shared `Input`/`Select` components, and extract one shared email validator function to replace the two separately-defined (but identical) email regexes in `AdminCreatePage.tsx` and `ProfilePage.tsx`.

## Definition of Done (copied from use cases)
- [x] AC-02.4 Given a syntactically valid email, when checked by the shared validator, then no email-format error results.
- [x] AC-02.5 Given the shared `Input`/`Select` components are used, when any form renders, then visual appearance (label, spacing, border, focus ring) is unchanged.
- [x] UC-02-E1 Given an email with leading/trailing whitespace, when validated, then it's trimmed before validation and accepted (matches current `.trim()` behavior).
- [x] UC-02-E2 Given an empty email field, when validated, then it fails with the same "valid email" error.
- [x] UC-02-E3 Given an extremely long (300+ char) but syntactically valid email, when validated, then it's accepted without crashing or truncating.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Current duplicated pattern: `AdminCreatePage.tsx`'s module-level `EMAIL_PATTERN = /^[^\s@]+@[^\s@]+\.[^\s@]+$/` and `ProfilePage.tsx`'s inline `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` in `handleSaveInfo` — same pattern, defined twice; extract to one function (e.g. `frontend/src/lib/validators.ts`, alongside the existing `frontend/src/lib/password.ts` pattern).
- Reference for input styling to extract: the repeated class string `"mt-1.5 block w-full rounded-lg border border-slate-300 px-3.5 py-2.5 text-sm text-slate-900 placeholder:text-slate-400 focus:border-slate-400 focus:outline-none focus:ring-2 focus:ring-slate-900/10"` appears (with minor variants) in `AdminCreatePage.tsx`'s `TextField`/`SelectField`/`TextAreaField`, and inline in `ProfilePage.tsx`.
- This ticket builds and unit-tests the validator + components in isolation; AC-02.1–02.3 and UC-02-E4 (full end-to-end form behavior) are verified in T-006 once the forms are migrated.
- Do not touch password validation — `lib/password.ts` and `PasswordField.tsx` already exist as the correct shared pattern and are out of scope here.
