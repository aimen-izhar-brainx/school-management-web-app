# T-013: Class CRUD API (backend)
- Milestone: M1
- Depends on: T-012
- Use cases: UC-01, UC-02, UC-03, UC-04, UC-05

## Goal
Add the `Class` Prisma model and a `classes` NestJS module with CRUD endpoints, enforcing admin-only writes via the guards from T-012.

## Definition of Done
- [x] AC-01.2 Given a class was just created, when fetched again (e.g. via the list endpoint), then it is present (persisted in Postgres).
- [x] AC-01.3 Given an empty class name, when the create endpoint is called, then it responds 400 with message "Please enter a class name." and creates nothing.
- [x] AC-01.4 Given a class name that already exists (case-insensitive), when the create endpoint is called, then it responds 400 with message "A class with this name already exists." and creates nothing.
- [x] UC-01-E1 Given a whitespace-only name, when submitted, then it is treated as empty and rejected with the same message as AC-01.3.
- [x] UC-01-E2 Given a name longer than 100 characters, when submitted, then it is rejected with a clear length-limit error.
- [x] UC-01-E4 Given two concurrent create requests with the same unique name, when both reach the server, then only one class is created; the second fails with the AC-01.4 duplicate error (enforced by a DB unique constraint on `name`, not just an application-level check).
- [x] AC-02.2 Given a class was renamed, when fetched again, then the new name persists.
- [x] AC-02.3 Given the name is cleared to empty on rename, when submitted, then responds 400 with "Please enter a class name." and the original name is unchanged.
- [x] AC-02.4 Given the new name already belongs to another class, when renamed, then responds 400 with "A class with this name already exists." and the rename is not applied.
- [x] UC-02-E1 Given a rename to the class's own current name, when submitted, then it succeeds (not treated as a duplicate).
- [x] AC-03.2 Given a class is deleted, when fetched again (list/get), then it is gone and does not reappear.
- [x] AC-04.1 Given a logged-in Teacher, when calling create/rename/delete on `/classes`, then responds 403 Forbidden and no data changes.
- [x] AC-04.2 Given a logged-in Student, when calling create/rename/delete on `/classes`, then responds 403 Forbidden and no data changes.
- [x] UC-04-E1 Given a request whose JWT role claim doesn't match the DB reality is irrelevant — the guard decision is based solely on the signed JWT's role claim, not any client-supplied data.
- [x] UC-04-E2 Given no token or an expired token, when any `/classes` endpoint is called, then responds 401 Unauthorized.
- [x] AC-05.2 Given one or more classes exist, when the list endpoint is called, then all are returned.
- [x] AC-05.3 Given M1 scope, when the list endpoint responds, then no section/subject fields are included yet (those are added in M2 tickets).
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Prisma: add `model Class { id, name @unique, createdAt, updatedAt }` to `backend/prisma/schema.prisma`; run a migration.
- New module: `backend/src/classes/` (`classes.module.ts`, `classes.controller.ts`, `classes.service.ts`, DTOs for create/rename with `class-validator` — max length 100, trimmed non-empty string).
- Endpoints: `GET /classes`, `POST /classes`, `PATCH /classes/:id`, `DELETE /classes/:id`. Apply `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles('admin')` on the three write endpoints; `GET /classes` only needs `JwtAuthGuard` (any authenticated role, per CLAUDE.md's `/api` prefix convention).
- Case-insensitive uniqueness: either a Postgres case-insensitive unique index/citext, or a pre-check + catch the Prisma unique constraint violation (P2002) as the race-condition fallback for AC-01.4 / UC-01-E4.
- Register `ClassesModule` in `backend/src/app.module.ts`.
