# T-007: De-duplicate attendance table/badge rendering
- Milestone: M3
- Depends on: T-004
- Use cases: UC-03

## Goal
Extract the status-badge rendering, roster/empty-state list rendering, and percentage calculation logic shared between `AttendancePage.tsx` and `MyAttendancePage.tsx` into shared helpers/components, with no change in displayed data or styling.

## Definition of Done (copied from use cases)
- [x] AC-03.1 Given a section with a recorded day, when AttendancePage browses to it, then per-status badge styling (color classes, dot indicator) matches pre-refactor, via logic shared with MyAttendancePage.
- [x] AC-03.2 Given a student/parent with recorded entries for the selected month, when MyAttendancePage renders, then each entry shows the same badge style/label as AttendancePage (same shared component).
- [x] AC-03.3 Given a section/date with no record, when AttendancePage browses to it, then "Not marked yet for {section} on {date}" still appears.
- [x] AC-03.4 Given zero attendance entries for the selected month, when MyAttendancePage renders, then "No attendance marked for this month yet." appears and percentage shows "—" (never NaN or a divide-by-zero).
- [x] UC-03-E1 Given 0 marked days in the month, when percentage is computed, then it's null/"—", never a division by zero.
- [x] UC-03-E2 Given a large roster (50+ students), when AttendancePage renders the list, then it still renders without errors.
- [x] UC-03-E3 Given edit mode is active on AttendancePage and the admin changes section/date mid-edit, when the filter changes, then edit mode cancels automatically (existing behavior preserved through extraction).
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Files: `frontend/src/components/AttendancePage.tsx`, `MyAttendancePage.tsx`, and shared logic already partly centralized in `frontend/src/data/attendance.ts` (`statusInfo`, `summarizeEntries`, `monthlyStatsForSection`, etc. — reuse these, don't re-derive).
- What's duplicated at the component level (not in `data/attendance.ts`): the status-badge `<span>` markup (color classes + dot), the roster `<ul>`/empty-state pattern, and the edit-mode-reset-on-filter-change logic (`editedKey`/`draftKey` pattern) which appears with the same shape in both `AttendancePage` and `MarkAttendancePage` — only the `AttendancePage`↔`MyAttendancePage` pair is in scope per the plan; `MarkAttendancePage` is explicitly out of scope (see UC-03's "Not included").
- Depends on T-004 since it edits the same two files T-004 already migrated to `DashboardShell`.
