# T-011: Auth service test coverage
- Milestone: M5
- Depends on: T-010
- Use cases: UC-07

## Goal
Add Vitest unit tests for `AuthService` covering login, token refresh, logout, forgot-password, and reset-password, asserting the service's existing behavior (no behavior changes in this ticket).

## Definition of Done (copied from use cases)
- [x] AC-07.1 Given valid credentials (bcrypt hash matches), when `login` is called, then it returns an access token and a new refresh token, and creates a `RefreshToken` row.
- [x] AC-07.2 Given invalid credentials (wrong password or unknown email), when `login` is called, then it throws `UnauthorizedException('Invalid email or password.')` — the same message for both cases.
- [x] AC-07.3 Given a valid, unexpired, unrevoked refresh token, when `refresh` is called, then the old token is marked revoked and a new one is issued (rotation), both inside one transaction.
- [x] AC-07.4 Given a refresh token that is missing, revoked, or expired, when `refresh` is called, then it throws `UnauthorizedException('Session expired. Please sign in again.')`.
- [x] AC-07.5 Given `requestPasswordReset` is called for a known vs. an unknown email, then both resolve successfully with no thrown error (the known-email path creates a reset token + invalidates prior unused ones; the unknown-email path only burns equivalent time via `bcrypt.hash`) — response shape never reveals which case occurred.
- [x] AC-07.6 Given a valid, unused, unexpired reset token and a password that meets `meetsPasswordRules`, when `resetPassword` is called, then the user's `passwordHash` is updated, the token is marked `usedAt`, and all of that user's active refresh tokens are revoked.
- [x] AC-07.7 Given a reset token that is missing, already used, or expired, when `resetPassword` or `verifyResetToken` is called, then it throws `BadRequestException('This reset link has expired.')`.
- [x] UC-07-E1 Given a refresh token that was already rotated (revoked) by a prior `refresh` call, when `refresh` is called again with that same stale token, then it's rejected with the same "Session expired" error (reuse-after-rotation).
- [x] UC-07-E2 Given a reset-password request with a password that fails `meetsPasswordRules` (e.g. "weak"), when called, then it's rejected with `BadRequestException('Your password does not meet all the requirements.')` before the token is even looked up, and the token is not marked used.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- File under test: `backend/src/auth/auth.service.ts`. Constructor deps to mock: `UsersService`, `PrismaService` (including `$transaction`), `JwtService`, `MailService`, `ConfigService`.
- `PrismaService.$transaction` is called both as an array form (`requestPasswordReset`, `resetPassword`) and a callback form (`refresh`) — the mock needs to support both.
- Use NestJS's `@nestjs/testing` `Test.createTestingModule` (already a devDependency) to build the module with mocked providers, consistent with how `backend/test/app.controller.spec.ts` (the only existing test) is structured.
- Test file location: `backend/src/auth/auth.service.spec.ts` (co-located, matching Vitest + Nest convention).
- Depends on T-010 only so the new test file is written against the final lint config rather than needing a follow-up lint-fix pass.
