# T-020: Fixed Period schedule (backend)
- Milestone: M3
- Depends on: none
- Use cases: UC-16 (partial)

## Goal
Add the `Period` Prisma model and seed it once with the fixed 8:00 AM–1:00 PM, Monday–Friday school-day schedule (periods + breaks), per the `/plan` decision that periods are fixed and not admin-editable in v1.

## Definition of Done
- [ ] AC-16.3 Given the seeded `Period` rows, when queried in order, then their start/end times and break labels match the fixed 8:00 AM–1:00 PM schedule (periods + breaks like "Recess"/"Lunch").
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Prisma: add `model Period { id, order @unique, startTime, endTime, isBreak @default(false), label? }` and `enum DayOfWeek { mon tue wed thu fri }` to `backend/prisma/schema.prisma`, per `docs/plan.md`. Migration required.
- Seed script (e.g. `backend/prisma/seed.ts` or extend an existing seed mechanism if one exists) inserts a fixed ordered list of periods spanning 8:00–13:00 with 1–2 breaks — confirm exact slot count/duration with the user if not already decided (plan.md left this as the one open question from `/plan`).
- `GET /periods` endpoint (any authenticated role, read-only) so the frontend grid (T-023) can render headers/break rows without hardcoding them.
- No write endpoints — periods are not editable via API in v1.
