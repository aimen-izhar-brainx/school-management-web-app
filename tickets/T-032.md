# T-032: Attendance data model + teacher mark/edit endpoints (backend)
- Milestone: M1
- Depends on: none
- Use cases: UC-01, UC-02, UC-03, UC-04

## Goal
Add the `AttendanceSession`/`AttendanceEntry` Prisma models and an `attendance` NestJS module letting a section's class teacher submit today's attendance and edit it again the same day, enforcing ownership and the today-only rule.

- [x] AC-01.3 Given the submission is stored, then `submittedBy` is the teacher and `submittedAt` is the current time.
- [x] UC-01-E2: Teacher double-clicks submit rapidly → only one session is created (no duplicate rows/error).
- [x] UC-01-E4: Teacher not logged in / token expired → 401, redirected to login.

## Technical notes
- Prisma (`backend/prisma/schema.prisma`): add `enum AttendanceStatus { present absent leave }`, `model AttendanceSession` (`sectionId`, `date @db.Date`, `submittedById`, `submittedAt`, `updatedAt`, unique on `[sectionId, date]`) and `model AttendanceEntry` (`sessionId`, `studentId`, `status`, unique on `[sessionId, studentId]`). Leave `AttendanceEdit` for T-034. Run a migration.
- New module: `backend/src/attendance/` (`attendance.module.ts`, `attendance.controller.ts`, `attendance.service.ts`, a DTO validating `entries: { studentId: string; status: AttendanceStatus }[]`).
- Endpoints, both guarded with `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles('teacher')`:
  - `PUT /attendance/sections/:sectionId/days/:date` — upsert the session + entries. Service must: look up the section (404 if missing), check `section.classTeacherId === req.user.id` (403 otherwise, including when `classTeacherId` is null), check `date` is today's server date in `YYYY-MM-DD` form (reject otherwise with a clear message), and validate the request body covers exactly the section's current roster (`User` rows with that `sectionId` and `role: 'student'`) — reject with the missing/extra student(s) named if not.
  - `GET /attendance/sections/:sectionId/days/:date` — same ownership check, returns `{ entries, submittedBy, submittedAt, locked }` where `locked = date !== today`, or 404-shaped "not found" if no session exists yet (not an error — the frontend treats this as "nothing submitted").
- Upsert via the `[sectionId, date]` unique constraint (`prisma.attendanceSession.upsert`) so resubmission and the double-click case (UC-01-E2) update in place rather than erroring or duplicating. Replacing entries: delete-then-recreate the `AttendanceEntry` rows for that session in one transaction, or upsert each by `[sessionId, studentId]` — either is fine as long as it's atomic per request.
- "No audit log for teacher edits" (AC-02.2) is automatic in M1 since `AttendanceEdit` doesn't exist until T-034 — just don't write to it.
- Locking (UC-02-E1 / AC-04.1/.2): since `date` must equal today for this endpoint, any call with a non-today date is already rejected by the same check — no separate "locked" flag or scheduled job needed (see `docs/plan.md`'s decision log).
- Register `AttendanceModule` in `backend/src/app.module.ts`.
