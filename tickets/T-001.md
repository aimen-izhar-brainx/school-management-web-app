# T-001: Frontend test tooling setup
- Milestone: M1
- Depends on: none
- Use cases: none (infrastructure prerequisite for UC-01 through UC-05's frontend tests)

## Goal
Install and configure a frontend test runner (Vitest + React Testing Library) so later tickets can write component tests, matching the test runner already used in `backend/`.

## Definition of Done (copied from use cases)
- [x] Vitest, React Testing Library, `@testing-library/jest-dom`, and a DOM environment (jsdom) are installed as frontend devDependencies.
- [x] A `test` script is added to `frontend/package.json` (mirroring `backend/package.json`'s `test`/`test:watch` scripts).
- [x] One sample test is added for an existing component (e.g. `AuthShell.tsx`) asserting it renders without crashing and shows "Brainx School".
- [x] `npm run test` in `frontend/` runs and the sample test passes.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- `frontend/package.json` currently has no `test` script and no test dependencies at all (confirmed via `backend/package.json` comparison — backend already uses Vitest `^4.1.2`).
- Vite + Vitest integrate natively; a `vitest.config.ts` or a `test` block in `vite.config.ts` is needed, with `environment: 'jsdom'`.
- Place the sample test next to its component, e.g. `frontend/src/components/AuthShell.test.tsx`, to establish the convention later tickets (T-002, T-005, T-007, T-008) will follow.
