# T-030: Reject invalid timetable entries (backend)
- Milestone: M3
- Depends on: T-021
- Use cases: UC-24

## Goal
Make the timetable-entry write endpoint reject requests sent straight to the API that the UI would never send: break periods, subjects not on the class, subjects without a teacher, unknown IDs, bad days and missing fields.

## Definition of Done (copied from use cases)
- [x] AC-24.1 Given the period is the break period (Recess), when sent, then responds 400 "Cannot schedule a subject during a break." and no entry is created.
- [x] AC-24.2 Given a subject that is not assigned to the section's class, when sent, then responds 400 "This subject is not assigned to this class." and no entry is created.
- [x] AC-24.3 Given a subject that is assigned to the class but has no teacher, when sent, then responds 400 "Assign a teacher to this subject first." (same message as AC-13.3) and no entry is created.
- [x] AC-24.4 Given a section, period or subject ID that doesn't exist, when sent, then responds 404 and no entry is created.
- [x] AC-24.5 Given a day other than mon–fri (e.g. "sat"), when sent, then responds 400 and no entry is created.
- [x] UC-24-E1: A required field is missing → responds 400 with a message that names the missing field.
- [x] UC-24-E2: The request includes a teacherId that is different from the class-subject's assigned teacher → the server ignores it and always uses the teacher from the class-subject assignment (UC-10), so the client can't choose the teacher.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Target: `PUT /sections/:sectionId/timetable/:periodId/:dayOfWeek` (body `{ subjectId }`) in `backend/src/timetable/` (T-021).
- Validate `dayOfWeek` against the `DayOfWeek` enum (e.g. a `ParseEnumPipe`). Validate `subjectId` with a `class-validator` DTO (required, string).
- For UC-24-E2, keep the DTO whitelist on (`whitelist: true`) so an extra `teacherId` field is removed. Check that the global `ValidationPipe` in `backend/src/main.ts` already does this; if `forbidNonWhitelisted` is on, it would return 400 instead, which breaks E2.
- Check in this order: section exists → period exists → period is not a break → subject exists → subject is on the class → class-subject has a teacher. The 404s come first, so an unknown ID never gets a misleading 400.
- AC-24.3 shares its check with AC-13.3 (T-021). Don't add a second copy.
