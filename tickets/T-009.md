# T-009: Enable frontend TypeScript strict mode
- Milestone: M4
- Depends on: T-007, T-008
- Use cases: UC-05

## Goal
Enable `strict: true` in `frontend/tsconfig.app.json` and fix every type error it surfaces, without changing any runtime behavior.

## Definition of Done (copied from use cases)
- [x] AC-05.1 Given strict mode is enabled, when `tsc -b` runs, then it completes with zero type errors.
- [x] AC-05.2 Given strict mode is enabled, when `npm run build` runs, then `vite build` still produces a working production bundle.
- [x] AC-05.3 Given the strict-mode fixes are applied, when manually exercising login → each of the 10 pages → sign out in dev mode, then there is no new runtime behavior change caused by the type fixes (no new unhandled exceptions).
- [x] UC-05-E1 Given a fix required adding a null-check where the compiler previously allowed implicit `any`, when that code path is exercised with the same previously-unsafe input, then it behaves the same as before — the fix satisfies the compiler only, not a new runtime behavior.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- File: `frontend/tsconfig.app.json` — add `"strict": true` to `compilerOptions` (currently only `noUnusedLocals`/`noUnusedParameters`/`noFallthroughCasesInSwitch`/`erasableSyntaxOnly` are set).
- Run last among the frontend milestones (after T-002–T-008) so strict-mode fixes apply to the final, de-duplicated code rather than code that gets rewritten again immediately after.
- Expect errors mainly around optional props without defaults, `Record<string, X>` lookups returning possibly-`undefined` (e.g. `grid[period.id]`, `records[key]` throughout the attendance/timetable pages), and event handler typing.
- Manual regression pass required per AC-05.3 — there is no automated e2e suite yet, so this is a manual click-through of login + all 10 pages + sign out.
