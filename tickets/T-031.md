# T-031: Block Parent role from Academic Management (backend + frontend)
- Milestone: M4
- Depends on: T-024, T-025
- Use cases: UC-25

## Goal
Make sure the Parent role can't change or read any Academic Management data, and that the UI shows a clear message instead of a broken page.

## Definition of Done (copied from use cases)
- [ ] AC-25.1 Given a logged-in Parent, when calling any write endpoint from M1–M3 (classes, sections, subjects, class-subjects, student assignment, timetable entries), then responds 403 Forbidden and no data changes.
- [ ] AC-25.2 Given a logged-in Parent, when calling `GET /timetable/me`, then responds 403 Forbidden.
- [ ] AC-25.3 Given a logged-in Parent, when opening the "My Timetable" page, then it shows "Not available for your role." with no grid and no error, and the Classes and Timetable builder pages have no admin controls.
- [ ] UC-25-E1: No token / expired token → 401 Unauthorized, same as other roles.
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- AC-25.1 needs no new guard code: every write endpoint is already `@Roles('admin')`. Add one test per controller (classes, sections, subjects, class-subjects, `PATCH /users/:id/section`, timetable) that calls it with a `role: 'parent'` JWT and expects a 403 with no data changes.
- AC-25.2: put `@Roles('teacher', 'student')` on `GET /timetable/me` (T-024). Admin also gets a 403 then, which is consistent with UC-21's "Not included".
- AC-25.3: in `frontend/src/components/MyTimetablePage.tsx`, if `user.role === 'parent'`, render "Not available for your role." and skip the fetch. Also check that the Classes and Timetable builder pages hide every write control for a parent, not just for teacher/student (`role !== 'admin'` rather than a list of excluded roles).
