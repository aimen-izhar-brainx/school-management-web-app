# T-033: Wire MarkAttendancePage to real API, with same-day re-edit (frontend)
- Milestone: M1
- Depends on: T-032
- Use cases: UC-01, UC-02

## Goal
Replace `MarkAttendancePage`'s in-memory mock state with real calls to the `/attendance` endpoints from T-032, and let the teacher re-edit today's submission instead of locking immediately.

## Definition of Done (copied from use cases)
- [x] AC-01.1 Given the teacher has not yet submitted today's attendance for their section, when they submit a status for every enrolled student, then the system saves it and shows the submitted summary (counts per status).
- [x] UC-01-E1: Section has zero enrolled students → nothing to submit, page shows "No students enrolled."
- [x] UC-01-E3: Network fails mid-submit → error shown, nothing partially saved, teacher can retry.
- [x] AC-02.1 Given today's attendance was already submitted, when the teacher changes a student's status and saves, then the new status is persisted and shown immediately.
- [x] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Files: `frontend/src/components/MarkAttendancePage.tsx`, its co-located `MarkAttendancePage.test.tsx`.
- Section picker: this page currently lists every section (`SECTION_OPTIONS` from the mock `data/timetable.ts`). Replace it with the teacher's own section(s) only: fetch `GET /classes` then `GET /classes/:classId/sections` for each (same pattern already used in `TimetablePage.tsx`), filter client-side to sections where `classTeacherId === user.id`. If none match, show "You are not the class teacher for any section." instead of a picker.
- Replace `INITIAL_ATTENDANCE_RECORDS`/local `records` state with `GET /attendance/sections/:sectionId/days/:date` on mount and whenever section/date changes.
- Decision during /build: T-032's GET endpoint as originally built only returned bare `{studentId, status}` entries and a 404 when nothing was submitted yet — insufficient for rendering a full roster with names before any submission exists. Extended it (still this ticket's scope, not a new ticket) to always return 200: `{ submitted: false, locked, entries: [{student:{id,name}, status: null}, ...] }` when nothing's submitted, or `{ submitted: true, locked, submittedBy, submittedAt, entries: [{student, status}], edits: [] }` when it is. `locked` is `date !== today` in both cases (an earlier pass hardcoded `locked: false` in the "no session" branch — fixed, with a regression assertion added to `attendance-date.spec.ts`). The PUT endpoint's contract is unchanged.
- `handleSubmit` calls `PUT /attendance/sections/:sectionId/days/:date` with `{ entries: [...] }`; on success, re-render the "Submitted" summary from the response.
- Key behavior change from the current mock: once submitted, keep showing an "Edit" control (not just the locked read-only view) as long as the selected date is still today, calling the same `PUT` endpoint again on save. Only show the "locked, contact admin" message once the date is no longer today.
- Use `ApiError.message` for the existing error-display pattern; on network/server failure during submit, keep the draft entries in place so the teacher can retry (UC-01-E3).
- `rosterFor`/`SECTION_ROSTERS` mock data is no longer the source of the student list — the roster comes from the `GET` response's `entries`, joined with each student's `name` (the backend's `User` model has no roll-number field, unlike the mock's `AttendanceStudent.rollNumber` — drop the "Roll no." display, it has no real-data equivalent).
