# T-029: Delete class confirmation with impact counts (frontend)
- Milestone: M2
- Depends on: T-014, T-028
- Use cases: UC-23

## Goal
Upgrade the "Delete class" confirmation on `ClassesPage`. If the class has sections, subject assignments or students, the dialog states the counts from T-028 before the admin confirms.

## Definition of Done (copied from use cases)
- [ ] AC-23.1 Given a class with sections, subject assignments or assigned students, when Admin clicks "Delete class", then the confirmation shows the counts, e.g. "Deleting Grade 5 will also delete 2 sections and 4 subject assignments. 30 students will be unassigned from their section."
- [ ] AC-23.2 Given Admin confirms, when the request completes, then the class, its sections, its subject assignments and its sections' timetable entries are all gone, both immediately and after reload.
- [ ] AC-23.5 Given Admin cancels the confirmation, then nothing is deleted or unassigned.
- [ ] UC-23-E1: A class with no sections, subjects or students shows the plain UC-03 confirmation, with no counts.
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- File: `frontend/src/components/ClassesPage.tsx` + `ClassesPage.test.tsx`.
- When "Delete class" is clicked, call `GET /classes/:id/delete-impact`. If all counts are 0, show the existing UC-03 confirmation. Otherwise show the message with the counts. Leave out any part whose count is 0, and use singular wording for a count of 1.
- After the delete succeeds, remove the class and its sections/subjects from local state and clear the selection (AC-23.2 "immediately").
- If the impact request fails, show the generic "Something went wrong. Please try again." error and don't open the dialog.
