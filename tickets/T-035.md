# T-035: Wire AttendancePage browse & edit + audit log to real API (frontend)
- Milestone: M2
- Depends on: T-034
- Use cases: UC-05, UC-06

## Goal
Replace the "Browse & edit" section of the admin `AttendancePage` mock with real data from T-034's endpoints, showing the edit log after a correction.

## Definition of Done (copied from use cases)
- [ ] AC-05.3 Given a saved edit, when the edit log is viewed, then it shows old status → new status, editor name, and timestamp, one entry per changed student.
- [ ] AC-06.1 Given a section+date with a recorded session, when Admin browses to it, then all student statuses, who submitted it and when, and the edit log (if any) are shown.
- [ ] AC-06.2 Given a section+date with no session, when Admin browses to it, then "Not marked yet" is shown instead of an error.
- [ ] UC-06-E1: Date filter set to a future date → "Not marked yet" (not an error).
- [ ] UC-06-E2: Admin browses a section with zero enrolled students → empty roster shown, no crash.
- [ ] All tests pass. Reviewer approved. Verifier passed.

## Technical notes
- Files: `frontend/src/components/AttendancePage.tsx`, its co-located test file(s) — only the "Browse & edit" section in this ticket; the two report tables are T-037.
- Section picker: build the flat section list the same way `TimetablePage.tsx` does (`GET /classes` then `GET /classes/:classId/sections` per class, flattened) — admin sees every section, unlike T-033's teacher-scoped picker.
- Replace `records`/local state for the browse panel with `GET /attendance/admin/sections/:sectionId/days/:date` (T-034) on section/date change; a "not marked yet" response renders the existing dashed empty-state box (AC-06.2 / UC-06-E1), not an error.
- `saveEditing` now calls `PATCH /attendance/admin/sections/:sectionId/days/:date` (T-034) with only the changed entries (or the full set — the backend only acts on real changes per UC-05-E1); on success, re-render from the response, including its `edits` array for the "Edit log" list (AC-05.3).
- Drop the "Roll no." column here too (see T-033's note — no roll-number field in real data).
- UC-06-E2 (zero enrolled students): the roster list renders empty but the page itself shouldn't crash — same empty-roster handling pattern as `MarkAttendancePage`.
